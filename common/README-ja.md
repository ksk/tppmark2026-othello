# 共通ルール：4×4・6×6 Othello

[English](README.md) | [日本語](README-ja.md)

両サイズで変わるのは一辺の長さだけです．マスを左上から行ごとに番号付けし，盤面をその順のリストで表します．
初期配置は中央の4石で，左上・右下が白，右上・左下が黒です．黒が先手です．

1. 空きマスに自分の石を置きます．縦・横・斜めの8方向で，隣のマスから1個以上の相手の石が連続し，その直後に自分の石があれば，その列を挟んだことになります．
2. 少なくとも1方向で石を挟める手だけが合法です．着手前の盤面ですべての反転対象を求め，石を裏返して自分の石を置きます．盤の端を越えてつながることはありません．
3. 手番を交代します．合法手がなく，相手には合法手がある場合は必ずパスします．合法手があるときはパスできません．
4. 両者とも合法手がなければ終局です．空きマスが残っていても構いません．盤上の石数が多い方が勝ち，同数なら引き分けです．

## 共通ルールと証明書との接続

| ファイル | 役割 |
|---|---|
| [common/Rules.v](Rules.v) | 一辺の長さを引数として，両サイズに共通するルールを定義 |
| [4x4/Rules.v](../4x4/Rules.v) | 4×4の証明書の検査で使う具体的なルールと型 |
| [6x6/Rules.v](../6x6/Rules.v) | 6×6の証明書の検査で使う具体的なルールと型 |

証明書の検証器では，それぞれの具体的な型と，リストで盤面を表すルールを使います．
証明書からこれらの型を直接使えるよう，共通ルールと重複する定義も含んでいます．
以下の同値性の証明で，各実装と共通定義を対応付けています．
検査を効率よく行うための盤面表現については，[6x6/README-ja.md](../6x6/README-ja.md)で説明しています．

`Dimension.side` は一辺の長さ，`Pieces` は証明書側の色・マスの内容・方向の型を与えます．
[boards/Four.v](../boards/Four.v) と [boards/Six.v](../boards/Six.v) が，それぞれの型と一辺の長さを共通定義に渡します．

[proofs/equivalence/](../proofs/equivalence/) で，合法な着手，合法手一覧，パスの条件，終局，石数，初期配置が一致することを証明しています．
戦略についても対応を証明し，証明書の検査結果を共通定義による解答へつなげています．
これらの同値性は，任意の盤面について成り立ちます．

## 何を証明しているか

`forces who goal board turn` は，`who` が相手の**どの合法手に対しても**，`goal` を満たす終局に至る有限の戦略を持つことを表します．
自分の手番では1手を選び，相手の手番ではすべての合法手を扱い，強制されるパスも含めます．

`black_score` は黒石数から白石数を引いた値です．
`exact_score b p z` は，盤面 `b`，手番 `p` から始めたとき，終局時に黒が `z` 以上を保証する戦略と，白が `z` 以下を保証する戦略の両方があることを表します．
この `z` をゲームの値と呼びます．
二つの戦略を対戦させるとその石数差で終局することと，ゲームの値が一意であることも証明しています．

最善手は，ゲームの値を保つ合法手です．
`optimal_replay z b p actions` は，盤面 `b`，手番 `p` から始まる，合法な着手と強制パスの有限の列を表します．
最後を含むすべての局面でゲームの値が `z` であり，最後の盤面が終局であることを要求します．

初期配置，問題文，証明は [4×4](../solutions/Othello4x4.v)・[6×6](../solutions/Othello6x6.v) を参照してください．
4×4では白が勝利を保証でき，6×6のゲームの値は−4です．

## 定義と補助定理

| 定義 | 内容 | 補助定理 |
|---|---|---|
| [Rules.v](Rules.v) | 盤面，初期配置，方向，反転，着手，パス，終局 | [RuleFacts.v](proofs/RuleFacts.v) |
| [Specification.v](Specification.v) | 石を挟む関係と合法な着手を，関係として記述 | [SpecificationFacts.v](proofs/SpecificationFacts.v) で実行可能なルールとの一致を証明 |
| [Game.v](Game.v) | 有限の戦略，石数差の上下限，対局，最善手 | [GameFacts.v](proofs/GameFacts.v) で戦略同士の対戦，ゲームの値の達成と一意性，最善手を選び続けた対局の結果を証明 |

関係による仕様では，計算用の関数を呼ばずに石を挟む条件を記述しています．計算が意図したルールを表しているかを確かめるためです．
6×6の[戦略に関する結果](../6x6/Semantics/Optimal.v)と[最善手による対局に関する結果](../6x6/Semantics/OptimalReplay.v)は，証明を重複させず，共通の定理を使います．
